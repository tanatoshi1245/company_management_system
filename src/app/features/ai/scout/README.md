# features/ai/scout — ② スカウト文面の AI 作成（`/ai/scout`）

## 役割
目的（文面の作成 / 添削）・既存企業（ボードに出ている企業だけ）・求人の内容・送る相手の条件を入れて実行すると、Worker が「類似業界 × 直近 1 年で返信率の高い文面」を分析し、作り方の違う 3 つのモデルが 1 案ずつ作る。**応答（十数秒）に結果が入っている**（2026-11-27 ユーザー指示で作り直し。セッションを立ち上げて待つ方式はやめた。ポーリングはしない）。CS が案を選び、企業が使ったかを記録すると、モデルごとの検証・チューニング（週次 + 管理者の手動）に使われる。

上の段 = 左 入力と履歴 / 右 タブ「結果」（何をもとに作ったか・分析結果）/「モデルの成績」、下の段 = 3 つの案（入力の列の下まで使う全幅。狭い画面では縦）。

- **何をもとに作るか（2026-11-27 ユーザー指示。使う人が最初に選ぶ）**: 既存企業の次に、4 つの作り方をカード（ラジオ）で出す（`SCOUT_BASIS_LABEL`・`SCOUT_BASIS_DESCRIPTION`）。**選ぶまでは、その先の入力欄と実行ボタンを出さない**（既定で選んだ状態にしない）。選ぶ・確かめるだけでは AI は動かず、実行ボタン（「この内容で文面を作る」/「この内容で添削する」）で初めて動く。目的（作成 / 添削）は、どの作り方とも組み合わせられる。
  - `conditions`（条件を指定）: 下の「入力」のとおり。
  - `job`（求人 ID）: 求人 ID →「求人を確かめる」→ 求人のカード（タイトル・職種・勤務地・年収・語学力・掲載中か・仕事内容と応募条件の先頭。掲載が終わった求人は注意）。ポジション名・掲載職種・勤務地の欄は出さず、送らない（Worker が求人の値を使う）。業界・言語・補足と、送る相手の条件は指定できる。
  - `member`（会員 ID）: 会員 ID →「候補者を確かめる」→ 候補者のカード（属性だけ。氏名・連絡先は無い）と、分析対象の絞り込みに使う条件（`summary.filters`）のチップ。求人の内容は自分で入れる。送る相手の条件の欄は出さず、送らない。
  - `jobMember`（求人 ID + 会員 ID）: 両方を確かめる。ポジション名などの欄も、送る相手の条件の欄も出さない。
  - **必要な ID がすべて確かめられるまで、実行できない**（理由をボタンの横に出す）。「確かめた」と扱うのは、いまの企業・いまの ID を確かめたときだけ（`useScoutLookup` の key）。ID を変える・企業を変える（求人）と確認が消える。404 は欄の下に理由。ID の欄の Enter は「確かめる」（フォームの送信 = AI の実行にしない）。
- **入力**（条件を指定）: 既存企業 → 目的 → （添削なら件名と本文。必須）→ 求人の内容（業界・ポジション名・掲載職種・勤務地・文面の言語・補足）→ 送る相手の条件（年齢層・国籍・日本語力・英語力・現住所・経験職種。各 8 個まで。選択肢はマートにある値だけ。年齢層・国籍は押して選ぶチップ、ほかは一覧から選ぶ）。条件を指定すると、その条件の送信だけで分析し直す。
  - 企業を選ぶと、業界と掲載職種（上位 3 つ）が自動で入る（直せる。直した項目は上書きしない）。
  - **件名・本文・ポジション名・勤務地・補足に、企業名・メールアドレス・電話番号が入っていると実行できない**（`findPii` の block）。「株式会社」「〇〇様」は注意だけ。
- **実行中**: 入力を押せなくし、「分析して 3 つの案を作っています（10〜30 秒）」と経過秒を出す。作れなかったとき（`fire: failed`）は理由と「もう一度作る」（= 同じ入力で新しく依頼。立ち上げ直しの API は無い）。
- **結果**: 見出しの下に、何をもとに作ったか（`result.target`: 作り方・求人のタイトルと ID・候補者の要約（畳んである）。以前の結果 = `target` なしは出さない）→ 注意（warnings）→ 分析結果（畳める。分析対象・数値・要点）→ 3 つの案（モデル名と版・件名・本文・文字数・狙い・添削なら変更点・コピー・手直し・「この案を選ぶ」）→ 「どれも使わない」とコメント → 選んだ後の「企業が使いましたか？」（使った / 使わなかった / 未確認。送信実績と照合できたときは、送信・返信・採用の数）。
  - 手直し（`PUT …/edited`）は、結果と同じ形で、案の件名・本文だけを差し替えて送る（feedback は入れない）。画面では、元の結果に直した版の件名・本文を重ね、選択・実績（feedback）は元の結果のものを使う。
  - 「どれも使わない」を記録したことと、送ったコメントは、結果からは読めない（開いている間だけ画面が覚える）。
- **モデルの成績**: 検証とチューニング（最後の実行・結果・次の自動実行）、モデルごとの説明・いまの版・成績（作った案・判断された数・選ばれた率・使われた数・返信率・総合点）・版の履歴。管理者（`models.admin`）にだけ、プレイブックの表示・「今すぐ検証・チューニング」・「この版に戻す」（確認つき）を出す。
- 結果は企業ごとに残り、履歴から開ける（開くと、そのときの入力・作り方・ID が欄に入り、求人・候補者は自動で確かめ直す = GET だけ）。サンプルデータ中の見本は URL に入れず、選択・利用の記録は画面の中だけで持つ。

## 依存するデータ（画面要素 → API → 元）
| 画面要素 | API | 元 |
|---|---|---|
| 条件の選択肢 | `GET /api/ai/scout/options` | マート（`dataDate` が null = 分析用のデータがまだ無い） |
| 求人の内容を確かめる | `GET /api/companies/:id/ai/scout/jobs/:jobId`（その企業の求人でなければ 404。AI は動かない） | Worker（マート） |
| 候補者の情報を確かめる | `GET /api/ai/scout/members/:memberId`（無ければ 404。AI は動かない） | Worker（マート） |
| 実行と結果 | `POST /api/companies/:id/ai/jobs`（`kind: scout`。同期） | Worker（マート + Vertex AI）→ D1 `ai_jobs` |
| 選択 / 利用の記録 | `PUT /api/ai/jobs/:jobId/scout/choice`・`…/scout/usage` | D1 |
| モデルの成績・チューニング・戻す | `GET /api/ai/scout/models`・`POST /api/ai/scout/tune`・`POST /api/ai/scout/models/:id/rollback` | D1 |

企業・履歴・手直しは [common/README](../common/README.md) の表のとおり。入力と結果の形は `src/shared/ai/scout.ts`（契約）。率・件数・文字数はすべて Worker が返した値で、画面は計算しない（特徴の横棒は割合の高い順に上位 8 個を出すだけ）。

## URL 状態
`company`（企業 ID）、`job`（開いている結果のジョブ ID。見本は入れない）、`purpose`（`template` 既定 / `review`）、`tab`（`result` 既定 / `models`）、`basis`（何をもとに作るか。無し = まだ選んでいない）、`jobId`・`memberId`（「確かめる」を押した ID。開き直すと自動で確かめる。作り方を変えると、使わない ID は外れる）。

## 編集するときの入口
- `ScoutPage.tsx`（割り付けと動き・選択と利用の記録）→ `scoutModel.ts`（フォーム → 入力、検証、社名・個人情報の確認、結果の読み取り、案の手直し、選択の状態、画面に出す文）
- `useScoutLookup.ts`（求人 ID・会員 ID を確かめる状態。key が同じときだけ「確かめた」）
- `components/ScoutForm.tsx`・`ScoutFilterFields.tsx`（入力）、`ScoutTargetCards.tsx`（求人・候補者のカードと、結果の「何をもとに作ったか」）、`ScoutResultView.tsx`（上の段 `ScoutResultTop` = 注意と分析結果 / 下の段 `ScoutResultView` = 3 つの案）・`ScoutAnalysis.tsx`（結果）、`ScoutModelsPanel.tsx`（モデルの成績）
- 文言は `src/shared/ai/options.ts`（`SCOUT_TEXT`・`AI_TEXT`）、見た目は `src/app/styles/ai.css` の「② スカウト」の節（色は `tokens.css` のトークンだけ。横棒は 1 系列 = `--accent`）
- 3 つの案は下の段（`.ai-col-wide`）。その幅が 1088px 以上のとき横に 3 枚（コンテナクエリ。1440 幅の画面で 1 枚の本文が 1 行 25 字）、それより狭いと縦
