# テスト環境（本番へ出す前に、見た目と動きを確かめる場所）

`main` へマージする前に、変更後のアプリを開いて確かめるための環境（2026-11-25 ユーザー指示。AI 機能のリリースから使う）。
確かめ方は 2 段ある。

| | ① PR プレビュー（設定なしで使える） | ② テスト環境（Worker `company-management-system-staging`） |
|---|---|---|
| 出る契機 | 作業ブランチへの push（Cloudflare の非本番ブランチのビルド） | `staging` ブランチへの push |
| 数値 | **サンプルデータ**（`BQ_MOCK=1`） | **本番と同じマート**（読み取りだけ。`BQ_MOCK=0`） |
| ログイン | なし（仮の利用者・閲覧のみ） | Google ドメイン認証（本番と同じ。Secret が無い間は 503） |
| 保存先（D1） | 書き込まない | テスト環境用の D1（本番とは別） |
| AI 機能 | **見本**が返る（セッションは立ち上げない。画面の見た目・入力・スライドの編集・PDF を確かめる） | **実際にセッションを立ち上げて**、結果がアプリへ返るまでを確かめられる（発火の Secret を登録したとき） |
| 画面の印 | 「サンプルデータ」 | 「テスト環境」 |

本番の Worker 名・URL・D1 は変えない。テスト環境は 1 つなので、同時に確かめられる変更は 1 つだけ（後から出した変更で上書きされる）。

## 使い方

1. 作業ブランチの内容を `staging` ブランチへ push する（Claude のセッションに「テスト環境で確認したい」と伝えれば、この push までを行う）。
   ```bash
   git push origin HEAD:staging --force
   ```
2. Cloudflare がビルドする（2〜3 分）。成否はテスト環境の Worker の **Deployments / Builds** で見る。
3. テスト環境の URL（`https://company-management-system-staging.<サブドメイン>.workers.dev`）を開いて確かめる。
4. 良ければ、プルリクエストを `main` へマージする（= 本番へのデプロイ）。直すときは、作業ブランチを直して 1 からやり直す。

`staging` ブランチは、テスト環境へ出すための写しで、毎回上書きする（`--force`）。**`staging` から作業ブランチを作らない・`staging` を `main` へマージしない。**

## 初回の設定（画面操作。約 20 分）

コード側の準備（`wrangler.jsonc` の `env.staging`）はリポジトリに入っている。以下は Cloudflare と Google の画面で行う。

### 1. `staging` ブランチ

Claude のセッションが作業ブランチを push して作る（GitHub の画面で `main` から作ってもよい）。

### 2. テスト環境の Worker を作る（Cloudflare）

**Workers & Pages → Create → Workers → Import a repository** で、本番と同じリポジトリ `tanatoshi1245/company_management_system` を選ぶ。

| 項目 | 値 |
|---|---|
| Worker name | `company-management-system-staging`（`wrangler.jsonc` の `env.staging.name` と同じ。この名前が URL になる） |
| Production branch | `staging` |
| Build command | 空欄 |
| Deploy command | `npx wrangler deploy --env staging` |
| Root directory | `/` |

- **Settings → Build → Branch control** で **Enable non-production branch builds をオフ**（テスト環境の Worker は `staging` だけをビルドする）。
- 初回のデプロイで、wrangler がテスト環境用の D1 `company-management-system-staging` を作って結び付ける。作られなかったときは「うまくいかないとき」。

この時点では Secret が無いので、URL を開くと 503「ログインの設定が完了していません」が出る（正常）。

### 3. D1 にテーブルを作る

Cloudflare → **Storage & Databases → D1 → `company-management-system-staging` → Console** で、`d1/migrations/` の SQL を番号の順（`0001` → `0004`）に貼って実行する。
手元に `wrangler login` 済みの環境があれば、次の 1 行でもよい。

```bash
npx wrangler d1 migrations apply CMS_DB --remote --env staging
```

### 4. Google ログインにテスト環境の URL を足す

[デプロイ手順](./デプロイ手順.md) 2 と同じ OAuth クライアントで、**承認済みのリダイレクト URI** に次の 1 行を追加する（既存の URI は消さない）。

- `https://company-management-system-staging.<サブドメイン>.workers.dev/auth/callback`

同じ画面で、テスト環境用の **クライアント シークレット** を 1 つ追加して控える（本番のものと分けておくと、片方だけを無効にできる）。

### 5. テスト環境の Worker に Secret を登録する

テスト環境の Worker の **Settings → Variables and Secrets** に登録して Deploy する。

| 名前 | Type | 値 |
|---|---|---|
| `GOOGLE_CLIENT_ID` | Secret | 本番と同じクライアント ID |
| `GOOGLE_CLIENT_SECRET` | Secret | 手順 4 で追加したシークレット |
| `SESSION_SECRET` | Secret | 新しく作ったランダム文字列（本番とは別の値。`openssl rand -base64 32`） |
| `BQ_SA_KEY` | Secret | 本番と同じ読み取り専用 SA（`cms-bq-reader@bq-hgt`）の鍵 JSON（1 行）。テスト環境も読み取りだけ |
| `AI_ROUTINE_ID`・`AI_ROUTINE_TOKEN` | Secret | AI 機能でセッションを実際に立ち上げて確かめるとき（[AI 機能](./AI機能.md)「セッションを立ち上げる設定」。本番と同じスケジュールタスクでよい） |
| `AI_ADMIN_EMAILS` | Text | セッションへのリンクを出す人のメールアドレス（カンマ区切り） |

テスト環境の SA には、書き込みの権限（スカウト未利用の登録の BigQuery への反映）を付けない。テスト環境で登録した理由・補足は、テスト環境の D1 にだけ残る（BigQuery は「未反映」のまま）。**テスト環境の「スカウト未利用」ページで「BQ に再同期」を押さない**（本番と同じ SA 鍵を入れたときは、本番の表に書き込まれる）。

### 6. 確かめる

1. テスト環境の URL を開くと Google のログインへ移り、会社のアカウントで入れること。左のレールに「テスト環境」が出ること。
2. `…/api/health` が `"mock":false` と、`ai` の設定の有無を返すこと。
3. 未ログイン（シークレットウィンドウ）で開くと、ログインへ移ること（`curl -i` なら 302、`/api/*` は 401）。

設定が済んだら、claude_analysis の `04_アプリケーション/セキュリティ要件.md` §5 の台帳に、テスト環境の Worker・リダイレクト URI・シークレット・鍵を足す。

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| ビルドが D1 の作成で失敗する・「D1 が設定されていません」と出る | wrangler が D1 を自動で作れなかった。Cloudflare の **Storage & Databases → D1** で `company-management-system-staging` を作り、その Database ID を `wrangler.jsonc` の `env.staging.d1_databases[0]` に `"database_id": "…"` として書いて、もう一度 `staging` へ push する |
| テスト環境を開くと本番の保存内容（目標・設定）が出る・「テスト環境」の印が出ない | Deploy command に `--env staging` が無く、本番の設定でデプロイされている。直して再ビルドする |
| 503「ログインの設定が完了していません」 | 手順 5 の Secret が未登録。テスト環境は、Secret が無い間は誰にも開かない |
| Google の画面で `redirect_uri_mismatch` | 手順 4 の URI が未登録か綴り違い |
| AI 機能で「保存できません」 | 手順 3 のマイグレーション（`0004_ai_jobs.sql`）が未適用 |

> 確認できていないこと（2026-11-25）: この文書の Cloudflare の画面の項目名は、本番の設定手順と wrangler の仕様から書いた。テスト環境の Worker を実際に作っての確認は、初回の設定のときに行う。
