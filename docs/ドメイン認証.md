# ドメイン認証（`@daijob.com` の Google アカウントだけが使える仕組み）

Worker に内蔵した Google ログイン（Cloudflare Zero Trust は使わない）。営業行動モニタリング（`sales_dashboard_IS-FS_ver2`）の実装を移植し、**未設定なら誰でも閲覧できる経路と Cloudflare Access 経路を削除**した（fail-closed）。
初期設定の手順は [デプロイ手順](./デプロイ手順.md) の 2 と 5。

## 仕組み

```
ブラウザ ──(未ログイン)──▶ Worker /auth/login ──▶ Google のアカウント選択（hd ヒント無し）
                                                      │ 認可コード
ブラウザ ◀──(Cookie 発行・元のページへ)── Worker /auth/callback ◀──┘
                                           ├ state と PKCE を照合（CSRF・コード横取り対策。cms_oauth Cookie、10 分）
                                           ├ コードを ID トークンに交換し、Google の公開鍵で署名・発行者・aud・期限・email_verified を検証
                                           ├ メールのドメインが ALLOWED_EMAIL_DOMAINS（daijob.com）か → 違えば 403（Cookie は発行しない）
                                           └ HMAC-SHA256 で署名したセッション Cookie（cms_session。7 日）を発行
以後のリクエスト（画面・assets・/api/*）: Cookie の署名と期限を Worker が確かめる。無い・壊れている・期限切れなら画面は 302、API は 401
```

| 状態 | 画面 | `/api/*` |
|---|---|---|
| `GOOGLE_CLIENT_ID` あり（本番） | セッション無し → `/auth/login` へ 302 | 401 `noSession` |
| `GOOGLE_CLIENT_ID` あり、`GOOGLE_CLIENT_SECRET` / `SESSION_SECRET` が無い | 503 | 503 `authConfig` |
| `GOOGLE_CLIENT_ID` 無し、`BQ_MOCK=1`（ローカル・PR プレビュー） | 仮の利用者 `preview@daijob.com`（`DEV_USER_EMAIL`）で閲覧のみ | 読み取りは通る。書き込みは 403 `readOnly` |
| `GOOGLE_CLIENT_ID` 無し、`BQ_MOCK≠1` | 503 | 503 `authConfig`（「URL を知っていれば誰でも」は無い） |

- 実装: `src/worker/auth/google.ts`（往復・Cookie）、`auth/jwt.ts`（ID トークン検証）、`auth/allowlist.ts`（許可リスト）、`auth/middleware.ts`（`authenticate` / `requireVerified`）、`auth/csrf.ts`（同一オリジン）、`index.ts`（順序: securityHeaders → authenticate → sameOriginGuard → requestLog → /auth → /api → assets）
- Cookie: `cms_session`（HttpOnly / Secure / SameSite=Lax / Path=/）、`cms_oauth`（ログイン往復の state + PKCE verifier、10 分）。他アプリ（`sam_session` 等）と衝突しない
- 書き込み（PUT / POST / DELETE）は Google ログインで確かめた人だけ（`requireVerified`）。モックの仮の利用者は読み取り専用
- 閲覧・編集の範囲: ログインした `@daijob.com` の人は全企業を閲覧でき、どの企業の目標・設定も編集できる（CS は互いに代理するため）。「担当」は絞り込みの属性で ACL ではない。すべての書き込みは D1 `audit_log` に編集者メール・前後の値・request_id を残す。絞るときは Text 変数 `ALLOWED_EMAILS` で利用者を限定する

## 設定の所在

| 場所 | 項目 | 値 |
|---|---|---|
| Google Cloud `bq-hgt` → Google Auth Platform → 対象 | 公開ステータス | 外部 / 本番環境（営業行動モニタリングで設定済み。`bq-hgt` は Workspace 組織に属さないため「内部」は選べない） |
| 〃 → クライアント | OAuth クライアント | **本アプリ専用**（§3.1「用途別に新規作成」）。ウェブ アプリケーション。リダイレクト URI = 本番 URL + `/auth/callback` のみ |
| 〃 → データアクセス | スコープ | `openid` / `email` / `profile` のみ（審査不要） |
| Cloudflare → Worker → Settings → Variables and Secrets | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `SESSION_SECRET` | Secret |
| `wrangler.jsonc` → `vars` / `previews.vars` | `ALLOWED_EMAIL_DOMAINS` | `daijob.com`（変えるときはファイルを直して `main` にマージ） |
| 〃（任意、ダッシュボードの Text 変数） | `ALLOWED_EMAILS` | 個別に許可するメール（`@partner.example` のようにドメインも可） |
| 〃（任意） | `SESSION_TTL_SEC` | 既定 604800（7 日） |

## 外部に見える情報

| 相手が開くもの | 返すもの |
|---|---|
| 画面・`/assets/*` | ログインへの 302（JS も配らない） |
| `/api/*` | 401 の JSON `{"error":"ログインしてください","code":"noSession","login":"/auth/login"}` |
| `/auth/login` | Google への 302（クライアント ID・戻り先・使い捨ての state / PKCE） |
| `/auth/callback` の失敗 | 一般的な文言だけ（許可ドメイン・Secret 名・環境変数名は出さない。詳細は Workers Logs） |
| エラー応答 | `{error, code, details?}`。スタック・SQL・ホスト名・Secret 名は含めない（`src/worker/lib/errors.ts`） |

ログイン後に見えるもの: `/api/health` は設定の有無（真偽値）、`/api/board` / `/api/companies/:id` は企業の実績・契約・担当の **名前**（担当のメールはログイン者本人の判定に使うだけで、応答には `owner.email` として既定の担当メールが含まれる。社内の `@daijob.com` アドレスであり PII ではないが、社外に渡さない）。求職者の氏名・連絡先は含まない（属性は集計件数のみ）。

## よくある変更

| やりたいこと | 手順 |
|---|---|
| 社外の人を 1 人だけ入れる | Text 変数 `ALLOWED_EMAILS` にメールを追加して Deploy |
| 許可ドメインを増やす | `wrangler.jsonc` の `vars` と `previews.vars` の `ALLOWED_EMAIL_DOMAINS` をカンマ区切りで直して `main` にマージ |
| 全員を一度ログアウトさせる | `SESSION_SECRET` を貼り替えて Deploy |
| クライアント シークレットを漏らした疑い | Google Auth Platform → クライアント → シークレットをリセット → `GOOGLE_CLIENT_SECRET` を貼り替え |
| ホスト名が変わる | OAuth クライアントのリダイレクト URI に新 URL + `/auth/callback` を追加（Worker 側は変更不要） |
| ログインを外す | できない（fail-closed）。検証はモック（`BQ_MOCK=1`）で行う |

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `redirect_uri_mismatch` | リダイレクト URI がエラー画面の `redirect_uri` と不一致。追加して数分待つ |
| 「このアプリは確認されていません」 | 外部 / 本番で出る注意。スコープが基本 3 つだけなので審査不要。「詳細 → 移動」で進める |
| 403「閲覧できません」 | 会社以外のアカウント。アカウントを切り替える |
| 「ログインの状態が一致しません」 | 10 分以上経過、または別ブラウザで戻った。やり直す |
| 503 `authConfig` | Secret が足りない。Workers Logs に名前が出る |
| 書き込みが 403 `readOnly` | モック（PR プレビュー・ローカル）で動いている。本番でログインして行う |
