# デプロイ手順（Cloudflare Workers + D1 + Google ログイン + 専用 SA）

コンソール作業はすべてユーザーが行う（Claude のセッションからは Cloudflare / Google Cloud コンソールに到達できない）。所要 40 分ほど。
順番: **1. BQ 専用 SA と鍵 → 2. OAuth クライアント → 3. D1 → 4. Worker（Git 連携）→ 5. Secret → 6. 確認 → 7. 台帳に記録**。
マート（`cms_*`）のスケジュールドクエリは 2026-10-23 に登録済み（`bq/README.md`）。

| 項目 | 値 |
|---|---|
| Worker 名 | `company-management-system`（`wrangler.jsonc` の `name`。Git 連携で付けた名前が優先される） |
| 公開 URL | `https://company-management-system.<サブドメイン>.workers.dev` |
| Node | 22（`.node-version`） |
| デプロイコマンド | `npx wrangler deploy`（`build.command` が `npm run build` を先に走らせる） |
| D1 | `company-management-system`（本番）/ `company-management-system-preview`（PR プレビュー） |
| BQ 読み取り | 専用 SA `cms-bq-reader@bq-hgt.iam.gserviceaccount.com`（読み取り専用。共用鍵 `bq-sa-key-for-claude` は使わない） |

## 1. BigQuery 専用サービスアカウントと鍵（Google Cloud `bq-hgt`）

セキュリティ要件 §3.1「用途別に新規作成・最小権限」。Workers は SA をアタッチできないので SA 鍵 JSON を Workers Secret に置く（§3.1 の「SA 鍵は最後の手段」の例外として README §セキュリティに明記）。

```bash
gcloud config set project bq-hgt
gcloud iam service-accounts create cms-bq-reader --display-name="契約企業マネジメントシステム BQ 読み取り"
# ジョブ実行（クエリを投げる権限。プロジェクト単位）
gcloud projects add-iam-policy-binding bq-hgt \
  --member=serviceAccount:cms-bq-reader@bq-hgt.iam.gserviceaccount.com --role=roles/bigquery.jobUser
# データ読み取りは dwh データセット単位（cms_* 以外も読めてしまうので、表単位にできるならそのほうがよい）
bq add-iam-policy-binding --member=serviceAccount:cms-bq-reader@bq-hgt.iam.gserviceaccount.com \
  --role=roles/bigquery.dataViewer bq-hgt:dwh
# 表単位にする場合（13 表に対して繰り返す）
# for t in cms_company_master cms_company_monthly cms_company_daily_usage cms_scout_cohort_status cms_application_cohort_status \
#          cms_scout_member_attributes_monthly cms_company_login cms_industry_benchmark_monthly cms_refresh_log; do
#   bq add-iam-policy-binding --member=serviceAccount:cms-bq-reader@bq-hgt.iam.gserviceaccount.com --role=roles/bigquery.dataViewer bq-hgt:dwh.$t
# done
# 鍵（発行日とキー ID を台帳 §5.2 に記録。90 日でローテーション）
gcloud iam service-accounts keys create /tmp/cms-bq-reader.json --iam-account=cms-bq-reader@bq-hgt.iam.gserviceaccount.com
python3 -c 'import json; print(json.dumps(json.load(open("/tmp/cms-bq-reader.json"))))'   # 1 行にして Secret に貼る
```

貼り終えたら `rm /tmp/cms-bq-reader.json`。鍵をチャット・スプレッドシート・リポジトリに置かない。

## 2. OAuth クライアント（本アプリ専用）

Google Cloud Console → **API とサービス → Google Auth Platform**（`bq-hgt`。同意画面は営業行動モニタリングで設定済みの「外部 / 本番環境」をそのまま使う）→ **クライアント → クライアントを作成**。

| 項目 | 値 |
|---|---|
| アプリケーションの種類 | ウェブ アプリケーション |
| 名前 | `契約企業マネジメントシステム（Worker）` |
| 承認済みのリダイレクト URI | `https://company-management-system.<サブドメイン>.workers.dev/auth/callback` だけ（ローカルで試すときだけ `http://localhost:5173/auth/callback` を追加し、終わったら消す） |
| JavaScript 生成元 | 不要 |

クライアント ID とクライアント シークレットを控える（シークレットはこの画面でしか見えない）。詳細は [ドメイン認証](./ドメイン認証.md)。

## 3. D1（本番 + プレビュー）

Cloudflare → **Storage & Databases → D1 → Create** で 2 つ作る（Workers Builds は D1 を自動作成できない）。

| 名前 | 用途 |
|---|---|
| `company-management-system` | 本番（`main`） |
| `company-management-system-preview` | PR プレビュー（`wrangler.jsonc` の `previews`） |

それぞれの **Database ID** を `wrangler.jsonc` の `d1_databases[0].database_id` と `previews.d1_databases[0].database_id` に書いて `main` にマージする。
マイグレーション（手元に `wrangler login` 済みの環境が必要。無ければ D1 のコンソールで `d1/migrations/*.sql` を順に実行）:

```bash
npx wrangler d1 migrations apply CMS_DB --remote             # 本番
npx wrangler d1 migrations apply CMS_DB --remote --preview   # プレビュー
```

## 4. Worker（Cloudflare の Git 連携）

1. 先に機能ブランチ → `main` の Pull Request をマージする（Production branch は `main`）。
2. **Workers & Pages → Create → Workers → Import a repository** → `tanatoshi1245/company_management_system`。

   | 項目 | 値 |
   |---|---|
   | Worker name | `company-management-system` |
   | Production branch | `main` |
   | Build command | 空 |
   | Deploy command | `npx wrangler deploy` |
   | Root directory | `/` |

3. Save and Deploy。ログに `[custom build] ✓ built in …` → `Deployed company-management-system` が出れば成功。
   この時点では Secret が無いので、開くと **503「ログインの設定が完了していません」**（fail-closed。意図どおり）。

## 5. Secret（Worker → Settings → Variables and Secrets → Add、Type = Secret）

| 名前 | 値 |
|---|---|
| `BQ_SA_KEY` | 手順 1 の 1 行 JSON |
| `GOOGLE_CLIENT_ID` | 手順 2 のクライアント ID |
| `GOOGLE_CLIENT_SECRET` | 手順 2 のクライアント シークレット |
| `SESSION_SECRET` | `openssl rand -base64 32` の出力（控え不要。変えると全員ログアウト） |

4 つ入れて **Deploy**。`Settings → Build` 側の「Build variables」はビルド専用なので入れない。`wrangler.jsonc` は `keep_vars: true` で以後のデプロイで消えない。
許可ドメインは `wrangler.jsonc` の `ALLOWED_EMAIL_DOMAINS = daijob.com`（社外の人を個別に通すときは Text 変数 `ALLOWED_EMAILS`）。

## 6. 確認（セキュリティチェックリスト §2.3 の実試験。結果を `docs/セキュリティチェックリスト.md` に記録）

```bash
URL=https://company-management-system.<サブドメイン>.workers.dev
curl -sI $URL/ | head -1                                   # 302 → /auth/login（未ログインは画面も配らない）
curl -s $URL/api/board | head -c 200; echo                 # 401 {"error":"ログインしてください","code":"noSession"}
curl -s -X PUT $URL/api/companies/1/targets/2026-10 -H 'content-type: application/json' -d '{}'   # 401
```

ブラウザでログイン（`@daijob.com`）後:

- `$URL/api/health` → `{"ok":true,"mock":false,"bqKeyConfigured":true,"d1Configured":true,"authMode":"google","googleLoginConfigured":true,"allowedDomains":["daijob.com"],...}`
- ボードに契約企業（約 390 社）が出る。初回は MISS（3 秒程度）、2 回目から HIT（DevTools の `x-cache` と `server-timing`）
- 個人の Gmail でログイン → 403「閲覧できません」
- 存在しない企業 `PUT /api/companies/999999999/targets/2026-10` → 404、cross-origin の PUT → 403、`content-type: text/plain` → 415（DevTools の Console から `fetch` で試す）
- 目標を 1 つ保存 → 設定 → 変更履歴に自分のメール。ボードを「目標比」にすると色が変わる

## 7. 台帳に記録

`claude_analysis/04_アプリケーション/セキュリティ要件.md` §5.1（アプリ）と §5.2（SA `cms-bq-reader@` のキー ID・発行日、OAuth クライアント）に追記し、`04_アプリケーション/README.md` の点検状況表の行を更新する（雛形の行は 2026-10-23 に追加済み）。

## PR プレビュー

`main` 以外のブランチは `npx wrangler preview` でビルドされ、`wrangler.jsonc` の `previews`（`BQ_MOCK=1`、プレビュー用 D1）で動く。Secret は無いので **サンプルデータ・読み取り専用**（書き込みは 403 readOnly）。モックの仮の利用者 `preview@daijob.com` で動くため、プレビュー URL も社外に渡さない。

## トラブルシュート

| 症状 | 対処 |
|---|---|
| 503 `authConfig`「ログインの設定が完了していません」 | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `SESSION_SECRET` のどれかが無い。Worker → Logs に足りない名前が出る |
| `redirect_uri_mismatch` | OAuth クライアントのリダイレクト URI がエラー画面の `redirect_uri` と完全一致していない。追加して数分待つ |
| 500 `noCredentials` | `BQ_SA_KEY` が無い。Secret の名前と入れる場所（Build ではなく Worker の Variables and Secrets）を確認 |
| 502 `bq`（`accessDenied`） | SA に `bigquery.jobUser` と `dwh` の `dataViewer` が付いているか。Worker → Logs の `BigQuery error [...]` |
| 503 `storage` | D1 が束ねられていない。`wrangler.jsonc` の `database_id` と Settings → Bindings を確認 |
| ボードが空・「マート更新に失敗」 | `bq-hgt.dwh.cms_refresh_log` の最新行が `error`。BigQuery Studio → スケジュールドクエリ（設定 ID は `bq/README.md`）の実行履歴を見る |
| マートを手動で再実行したのに画面が古い | 設定 → 「Worker のキャッシュを捨てる」（`cache_epoch` +1） |
| `Could not detect a directory containing static files` | Production branch にアプリが入っていない（`main` 未マージ） |
| `missing a previews block` | `wrangler.jsonc` の `previews` を消した。戻す |
