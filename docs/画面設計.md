# 画面設計（ルート・URL 状態・コンポーネント）

ルータは `src/app/router.tsx`（History API、React.lazy でルートごとに 1 チャンク）。状態は URL に持ち、戻る・リロード・共有で復元する。スクロール位置は history の state に保存し、戻る / 進むのあと画面が描けた時点で元の位置に戻す（`useScrollRestore`。2026-10-30〜）。計算（スコア・絞り込み・並べ替え）はブラウザ側（`src/shared/metrics/`）で、モード切替や絞り込みで再取得しない。

| ルート | 画面 | URL 状態（既定値は URL から消える） | API |

| `/` | ホーム（契約企業ボード、当月・契約中のみ。NW = Network 契約は出さない） | `mine=1`, `owner=a,b`, `type=a,b`, `ending=30\|60\|over90`, `sort`（列見出しのクリック）, `q` | `/api/board?month=`（当月） |
| `/companies/:id` | 企業詳細 | `from`, `to`（期間。既定 = 契約開始月〜当月）, `account`（アカウント種別。空 = 全体）, `tab=jobs\|scout\|selection`（既定 jobs）, `job=<set_id \| job_id \| direct>`（求人フィルタ）, `attr=<attribute_type>` | `/api/companies/:id?month=<to>`, `/api/companies/:id/attributes?from&to&account&job`, `/api/companies/:id/jobs?from&to&account&job` |

## 共通レイアウト

- `AppShell` + `LeftRail`（ロゴ・ナビ 4 項目・データの鮮度・ログイン中のメール・ログアウト）。本文は最大幅 1,440px。
- `PageHeader`（題・文脈行・右上の操作）。`Notice` は error（role=alert）/ warn / info。`Skeleton` は面色の 1.2 秒パルス。
- 色はデータにだけ使う（順序 `--seq-*`、発散 `--heat-*`、状態色はラベル併記）。アクセントはネイビー `#000066`、ゴールドはフォーカスリングとアクティブナビのみ。`prefers-reduced-motion` で動きは 0。

## ホーム `/`（features/home）

1. **PageHeader**: `契約企業ボード`、`2026年10月（営業日 17/21 経過・81%）・データは 10/22 まで・マート更新 10/23 07:52`、右に「最新に更新」。
2. **KpiStrip**（4 タイル。見出しと数字だけで、副説明・スパークラインは無い）: 契約企業数 / **アクティブ企業数（最終ログイン30日以内）** / **スカウト利用社数（利用率）**（1 件以上送信した契約中の企業数、括弧内は ÷ 契約中の企業数）/ **スカウト消化率**（Σ月間送信 ÷ Σ月間送信枠、枠のある契約企業）。**契約中の企業だけ**を数える。各タイルの数字の下に契約体系の内訳（左 = 広告掲載、右 = 成功報酬。社数、消化率だけ %。不明は合計にだけ含める）。見出しの文脈行に「マート更新」は出さない（左レールに表示）。表の企業名は広告掲載型を黄色でハイライト（凡例あり）。
3. **BoardFilterBar**（sticky）: 担当=自分（件数付き）・**CS 担当**（プルダウン・複数選択）・**企業種別**（プルダウン・複数選択: 直接 / 紹介 / 派遣 / RPO / DA / NW（NW・不明は 0 件なら出さない）。**既定は DA と RPO 以外**（2026-10-30〜。既定のままならチップは強調せず URL にも出ない）。判定は企業種別で、直接 / 紹介 / 派遣 の企業は副アカウントの種別でも一致する。DA / RPO のプロファイルも種別は 直接 / 紹介 だが企業種別で判定するので「直接」に混ざらない）・**契約終了**（プルダウン・単数: 30 日以内 / 60 日以内 / 90 日以上先）・**求人掲載**（すべて / あり / なし = 当月の掲載求人数 > 0 / = 0）・**スカウト送信**（すべて / あり / なし = 当月の送信数 > 0 / = 0）・検索・クリア。**フィルタ同士は連動する**（2026-10-30〜。`filterCompaniesExcept`）: CS 担当・企業種別の選択肢と件数、担当 = 自分 の件数は「その項目以外のフィルタを通った契約中の企業」から作る（企業種別で 直接 だけを選ぶと CS 担当には 直接 の企業の担当だけが出る）。選択中の値は 0 件になっても選択肢に残す。期間（月）・業種・並べ替えの選択は無い（並べ替えは列見出しのクリック）。
4. **CompanyBoard**（契約中の企業 × 実績）: 固定 3 列 = **種別**チップ・**CS 担当（苗字。既定は企業管理ツールの `active_companies.sales_staff`、画面での上書きが優先）**・企業名（メーター・アイコンは無し）。列グループ = 応募（掲載 / 枠（分数）・閲覧・応募）/ スカウト（送信 / 枠（分数）・返信（当月。返信月軸））/ 選考（選考中・採用）/ 接点（最終ログイン。日付のみ）/ 契約（契約残。日数のみ）。セルの副情報（消化率・期待値・/求人・送信月基準・n 日前・終了日）は出さず、式や注記はマウスオーバーのツールチップに置く。各列は薄いグレー（`--rule`）、列グループの先頭はやや濃いグレー（`--rule-strong`）の縦線で区切る。グループ見出し「接点」と列見出し「最終ログイン」はマウスオーバーで注釈（CT 画面へのログインは GA4 由来で、データは `meta.loginAvailableFrom` = 2026-05-15 以降のみ。それ以前しかログインが無い企業は「記録なし」= 30 日以上ログインなし扱い）を出す。**色は 0 件（掲載・閲覧・応募・送信）と 30 日以上ログインなしの赤だけ**。行クリックで詳細、ホバー 150ms で詳細を prefetch。
5. **BoardLegend**: 赤の意味と「契約中のみ」「営業日 n/N 経過」の注記。
6. 空状態 `EmptyBoard`（フィルタのクリア）。

## 企業詳細 `/companies/:id`（features/company）

`CompanyHeader`（名前・状態・種別・業種・プラン・アカウント（複数のときチップ）・ID、**期間の 2 セレクタ（開始月〜終了月。窓の 14 か月から。開始 > 終了にならないよう連動）とアカウント種別の `Segmented`（全体 | 直接 | 紹介 … 。複数アカウント企業のみ）**。その下にカード 3 枚: **契約期間（開始〜終了）/ 契約終了まで（残日数。60 日以内は黄）/ 最終ログイン（CT。30 日以上なし・記録なしは赤）**。担当 CS・SF 取引先・Salesforce・契約中の根拠・マート更新・契約残の棒は 2026-10-27 に削除）→ **`CompanyTabs`**（カードの下に 3 つを同じ幅で横並び。`tab=`）→ タブの中身（2026-10-30〜）。**求人の実績**: `SummaryPanel`（選択期間 from〜to のうち契約期間中の月の累積。掲載求人数（期間に掲載期間が重なる求人を `jobs` の一覧から set_id で重複排除して数える）/ 閲覧件数 / 応募件数 / 採用（応募経由））→ `grid-2`（`ViewsAppsPanel`（2 軸: 左 = 閲覧件数、右 = 応募件数）/ `AttributePiePanel`「誰が求人を見ているか」= 閲覧（`kind = view`）/ 応募（`kind = application`）の切替）→ **`JobsTablePanel`**（求人ごとの実績の表: 求人タイトル / アカウント / 掲載期間 / 閲覧件数 / 応募件数 / 採用。閲覧の多い順。上の「求人」プルダウンか行クリックで求人を選ぶと `job=` が付き、このタブのカード・推移・円グラフと選考状況がその求人の分（`/jobs?job=` の月次と `/attributes?job=`）になる。「解除」で戻る。`cms_company_job_monthly` を読めないときは権限待ちの注記）。**スカウトの実績**: `SummaryPanel`（スカウト送信件数 / 興味あり返信（返信月基準）/ 選考中（現在 = 終了月の値）/ 採用（スカウト経由）。求人フィルタは効かない旨を lead に）→ `grid-2`（`ScoutTrendPanel`（2 軸）/ `AttributePiePanel`「誰にスカウトを送っているか」= 送信 / 興味あり）→ `ScoutUnusedPanel`。**選考状況**: `SelectionPanel`（面接調整中 / 1st / 2nd / 3rd / Final / 採用 の 6 枚 = 期間の月の `st06〜st11` の合計。全体 = `monthly.st`、種別 = `accountMonthly.st`、求人選択時 = その求人の応募側）。アカウント種別を選ぶと実績・推移・求人の表は `accountMonthly` / `/jobs?account=` のその種別の分。`PieChart` は同一サイズ 200px のドーナツ、8% 以上のスライスに構成比、上位 7 件 + その他 + (未入力)、属性タブ 8 種（語学レベルは番号の降順）。`TargetVsActualPanel`（契約時の目標との比較）は 2026-10-27 から非表示（ファイルは残す）。

## スカウト未利用の理由 `/scout-unused`（features/scoutUnused）

`PageHeader`（対象は**前月固定**（2026-10-31〜。月の切替は無い。登録期間が終わった月は振り返らない）、「BQ に再同期（n）」は未反映があるときだけ。見出しの「n 社・登録済み n 社」は絞り込み後の件数）→ `sticky-bar`（担当 = 自分、**CS 担当**（プルダウン・複数選択）、**登録状況**（`<select>`: すべて / 未登録 / 登録済み / BQ 未反映）、**企業種別**（プルダウン・複数選択: 直接 / 紹介 / 派遣（不明は 0 件なら出さない）。副アカウントの種別でも一致）、**契約種別**（プルダウン・複数選択: 広告掲載 / 成功報酬）、クリア（全部消す）、検索。2026-10-30〜。選択肢の件数はボードと同じく他のフィルタに連動する）→ 表（`table-layout: fixed`。列幅 種別 64px / CS 担当 96px / 企業名 26% / 理由 30% / 補足 残り / 登録 150px。企業名は省略表示で `title` に全文）**種別 / CS 担当（苗字）/ 企業名（詳細へ。広告掲載の企業は薄い黄色 `--dj-gold-pale` で強調。凡例は説明文に）/ 理由（`<select>`: 未選択 + 8 件を 8 → 1 の順）/ 補足（500 文字）/ 登録（変更がある行だけ有効。両方空なら「削除」）+ 状態（未登録 / 登録済み（シート取込）/ BQ 反映済み / BQ 未反映・更新者・時刻）**。枠の列は無い（2026-10-30 に削除）。対象 = 前月に 1 日でも求人を掲載（`m.jobsInMonth > 0`）・前月の送信 0 件・今日時点で契約中（`state` = active / ending_30d）・DA / RPO / NW 以外（`isScoutUnused`。枠数では絞らない。2026-10-31〜）。BQ に既にある記録（シート取込）は入力欄の初期値としてそのまま出し、状態に「登録済み」。変更して登録するとアプリの登録が優先される（重複して数えない）。シートだけの行は画面からは消せない。閲覧のみ（`canEdit=false`）は入力を無効化。

## 目標 `/targets`・`/targets/:id`（features/targets）

- 一覧: `Chip`（担当=自分・未設定のみ）+ 検索 + 並べ替え。表 = 企業・プラン・担当・目標 5 項目・`TargetProgressBar` × 2（スカウト送信・応募）・最終更新。右上に「プラン既定値で未設定を埋める」（`BulkDefaultsDialog`、verified のみ）。
- フォーム: `MonthGridForm`（12 か月 × 8 行 + 備考。dirty な列は金色、不正値は赤枠、Enter で確定、列ごとに「前月からコピー」）、「プラン既定値を適用」、`save-bar`（未保存 n か月のバッジ・差分を保存・元に戻す）、`CompanySettingsForm`（担当上書き・枠の期間・枠の上書き・メモ）、`ChangeHistory`（監査ログ 30 件）。未保存のまま閉じると `beforeunload` の確認。

## 設定 `/settings`・ヘルプ `/help`（features/settings）

- 設定: データの鮮度 / Worker の設定の有無（真偽値のみ）+ `CacheBumpButton` / `PlanDefaultsEditor`（行 = プラン、列 = 8 指標、行ごとに保存）/ `OwnerOverrideList`。
- ヘルプ: `DefinitionsList`（`METRICS` と `DERIVED_DEFINITIONS` から生成）+ データの注意点（`/api/meta.caveats`）。
