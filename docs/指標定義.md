# 指標の定義

画面に出る数字の式・元の列・注意点。唯一の定義場所は `src/shared/metrics/definitions.ts`（指標レジストリ）で、ヘルプ画面もそこから生成する。ここはその人間向けの写し。

## 共通の前提

| 用語 | 定義 |
|---|---|
| 契約中 | Daijob の `companies.active_from ≤ 今日 ≤ COALESCE(active_to, 9999-12-31)`。Salesforce の契約（有効 / 成立商談 / DA 掲載中）は参考シグナル。RA（4928 / 14508）・RDS（7080）の企業と、`companies.publishing_sites` に `WAWW` を含む企業は対象外（マートに入らない） |
| 月 | 当月は MTD（データ最終日 = 昨日まで）。過去月は月の全日 |
| データ最終日 | `run_date − 1`（Aurora → BQ の日次ロードは前日分まで。スカウトは当日分を含まない） |
| 営業日 | 月〜金 のうち祝日（`src/shared/calendar/jp-holidays.json`）と会社の年末年始休業（12/29〜1/3）を除く |
| 営業日消化率 | 当月の経過営業日（データ最終日まで）÷ 当月の営業日数 |
| 契約経過率 | （契約開始からの経過日数 + 1）÷ 契約日数。スカウト枠の期間を「契約」にした企業のペース比較に使う |
| 期待値 | 枠数（または目標）× 営業日消化率 |

## 指標（ボードの列）

| 指標 | 式 | 元の列 | 高い方が良い | 業界比 | 目標比 | 注意 |
|---|---|---|---|---|---|---|
| 求人枠消化率 | 掲載中の求人数（set_id で日英重複排除）÷ 求人枠数 | `cms_company_monthly.active_jobs_eom` / `cms_company_master.job_posting_limit` | ○ | ○ | – | set_id_dedup |
| スカウト枠消化率 | 当月のスカウト送信数 ÷ スカウト枠数（月間枠）。ペース = 消化率 ÷ 営業日消化率 | `scout_sent` / `scout_limit` | ○ | ○ | ○（送信数） | scout_quota_period, scout_lag |
| 興味あり返信率 | 当月に送ったスカウトのうち興味あり返信があった数 ÷ 送信数（返信日は問わない） | `interested_by_send_month` / `scout_sent` | ○ | ○ | ○（興味あり数） | |
| 応募 / 求人 | 当月の応募数 ÷ 掲載中の求人数 | `applications` / `active_jobs_eom` | ○ | ○ | ○（応募数） | |
| 閲覧 / 求人 | 当月の求人閲覧数 ÷ 掲載中の求人数 | `job_views` / `active_jobs_eom` | ○ | ○ | ○（閲覧数） | |

## ボードの KPI タイル

| タイル | 式 | 注意 |
|---|---|---|
| 契約企業 | **契約中の企業数**（当月は今日時点で契約中、過去月はその月に契約期間が重なる企業。終了済み・開始前は表示もカウントもしない） | |
| スカウト消化率 | Σ 月間送信実績 ÷ Σ 月間送信枠（枠のある契約企業。枠の期間が「契約」の企業は除く） | 当月は営業日消化率と比べて色付け（80% 未満 = 赤、100% 未満 = 黄） |
| スカウト利用率 | 1 件以上送信した企業数 ÷ 契約中の企業数 | 50% 未満 = 赤、70% 未満 = 黄 |
| スカウトの消化率_進捗遅れ | ペース（消化率 ÷ 営業日消化率）が 0.8 未満 の企業数 | |
| 30 日以上ログインなし | CT 画面への最終ログインが 30 日以上前、または記録なし（2026-05-15 以降ログインなし）の企業数 | |

## ボードの列（実数）

種別 → CS 担当（苗字）→ 企業名 → 掲載 / 枠、閲覧、応募、送信 / 枠、返信（当月 = その月に興味あり返信があったスカウト数。送信月は問わない）、選考中、採用、最終ログイン（日付・n 日前）、契約残（日数）。
**色は 2 種類だけ**: 掲載・閲覧・応募・送信が **0 件** のセル、および **30 日以上ログインなし（記録なしを含む）** のセルを赤く強調する。業界比 / 目標比の 5 段階色はボードでは使わない（企業詳細の目標比較・ベンチマークでは使う）。

## ペース（スカウト）

| 判定 | 条件 |
|---|---|
| 判定前 | 経過営業日が 3 日未満 |
| 遅れ | 消化率 ÷ 営業日消化率 < 0.8 |
| 注意 | 0.8 〜 1.0 |
| 順調 | 1.0 〜 1.2 |
| 前倒し | > 1.2 |
| 枠なし | 枠数が 0 / 未設定 |

## ヒートマップの 5 段階（企業詳細の目標比較・推移の帯で使用。ボードでは使わない）

比率 = 実績 ÷ 基準（業界比は同群の中央値、目標比は期待値）。

| 比率 | スコア | 色 |
|---|---|---|
| < 0.5 | −2 | `--heat-n2`（赤・白文字） |
| 0.5 〜 0.8 | −1 | `--heat-n1` |
| 0.8 〜 1.2 | 0 | `--heat-0`（暖色の中立） |
| 1.2 〜 1.5 | +1 | `--heat-p1` |
| ≥ 1.5 | +2 | `--heat-p2`（紺・白文字） |
| 基準なし・データなし | – | 斜線 |

「低いほど良い」指標は符号を反転する（現在は該当なし）。中央値が 0 の群は、実績 > 0 なら +2、0 なら 0。

## 業界ベンチマーク

- 群 = 業種（`company_profiles.industry`、無ければ Salesforce の業種）× 企業種別（DA / RPO / 直接 / 紹介）。母集団はその月に契約中の企業
- `n_companies` が 5 社（`BENCH_MIN_N`）未満のときは 業種 × 全種別 → 全業種 × 種別 → 全体 の順で代替し、ツールチップに代替した群を出す
- 値は `cms_industry_benchmark_monthly` の中央値（p25 / p75 も持つ）

## 企業ヘルス

各指標のスコアの重み付き平均（スカウト 2、返信・応募・採用・求人枠 1、閲覧・ログイン 0.5）を四捨五入。

| 判定 | 条件 |
|---|---|
| 要注意 | 平均 ≤ −1 |
| 注意 | 平均 0 だが −1 以下の指標がある |
| 順調 | それ以外 |
| 判定なし | 比較できる指標が無い |
